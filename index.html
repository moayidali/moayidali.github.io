Sec.02 / Work
System designer · AdonisData integration

Employee data replication between the HR core and external systems

Problem

Employee records lived in two systems at once, so every change had to be re-entered by hand — and the drift was usually discovered downstream, by payroll.

What I did

Designed a two-stage replication flow: validate into staging tables before anything is written, then a controlled write-back to the external system. Mapped every branch — create a new person versus update an existing employee, documents, activity records — so developers had one unambiguous spec instead of a conversation.

How the replication flow worksDrag to rotate · step through the stages

Two systems holding the same employee, kept in agreement without anyone re-typing anything.

How the sync works, step by step
  1. Stage one — inbound. Incoming employee data is written to temporary staging tables and validated there. Nothing touches the internal system until the batch is clean.
  2. Person records. Where no matching person exists, one is created; where a match exists, the update is applied conditionally, field by field, rather than overwriting the record wholesale.
  3. Documents and activities. Attached documents and activity records are synchronised alongside the employee they belong to, so a record never lands half-complete.
  4. Stage two — write-back. Validated changes are replicated back to the external system in a controlled pass, which is what keeps the two systems in agreement instead of racing each other.
System designer · AdonisE-learning · SSO

Moodle integration for offshore crew training

Problem

Crew training had to reach people at sea, and every extra login was a barrier for someone on a vessel with intermittent connectivity.

Constraint

The same courses had to work across a web portal and a desktop application, enrolled centrally from an office but also on board, where the vessel only knows what it holds locally until it can reconcile.

What I did

Designed an e-learning solution that joins Moodle to the existing platform: single sign-on so no one manages a second password, and a replicator that handles enrolment differently office-side and vessel-side.

Integration architecture and enrolment logicStep through to follow each path

One training platform reached from the office and from sea, without a second password.

Integration architecture and enrolment logic
  1. Single sign-on. Authentication runs through Moodle's auth_userkey plugin, so a user already signed into the platform lands in the learning environment without a second set of credentials.
  2. Two front ends. The solution spans a web portal and a desktop application, with the mobile web experience designed for people completing assessments away from a desk.
  3. Office-side enrolment. Administrators enrol crew centrally, against the same person records the HR platform already holds.
  4. Vessel-side enrolment. On board, enrolment has to work with what the vessel knows locally and reconcile later — a different problem from the office case, and treated as one.
